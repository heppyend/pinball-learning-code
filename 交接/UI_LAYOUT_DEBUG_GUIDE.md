# UGUI 布局问题排查与修复指南（实战版）

> 来源：2026-09-21 大厅窄高比适配实战（1080×1920/2160 背景黑边 + 两个底栏重叠）。
> 整理成**可复用的五步法**。配套脚本：`Logs/ui-adapt-audit.ps1`、`Logs/ui-adapt-audit2.ps1`；运行时修正：`Assets/Client/Runtime/UI/ClientScrollFix.cs`。

---

## 0. 一句话心智模型

**UGUI 的每个矩形都是"跟着父级的某条边/某个比例走"，最后再加一个固定偏移。**

```
最终位置 = f(锚点 anchorMin/anchorMax, 父级尺寸)  +  anchoredPosition
最终大小 = f(锚点是否拉伸, sizeDelta, 父级)
```

所以**所有"错位/重叠/黑边"问题，本质都是"锚点类型不一致"或"画布形状变了"**。

---

## 1. 第一步：先算「画布有多少单位」——排查的起点

`CanvasScaler` 决定画布尺寸，关键是 `matchWidthOrHeight`：

| 模式 | 恒定的是 | 会变的是 | 公式 |
|---|---|---|---|
| **0（按宽）** | **宽 = 参考宽** | 高 | `高单位 = 参考宽 × (屏幕高 / 屏幕宽)` |
| **1（按高）** | **高 = 参考高** | 宽 | `宽单位 = 参考高 × (屏幕宽 / 屏幕高)` |
| 0.5（混合） | 都变 | 都变 | 最难设计，一般不要用 |

本工程：参考 `753×1630`、`match = 0` ⇒ **宽恒 753**，高按比例变：

| 分辨率 | 比例 | 画布高(单位) | 相对设计(1630) |
|---|---|---|---|
| 752×1630 | 2.168 | **1632** | ≈设计 ✓ |
| 1080×2280 | 2.111 | 1590 | 略矮 ✓ |
| 1080×2160 | 2.000 | **1506** | 矮 124 |
| 1080×1920 | 1.778 | **1339** | **矮 291** ✗ |

> **结论：比例比设计比例(2.166)矮 ⇒ 画布变矮；所有"跟顶边/跟中心"的东西都会朝底边压。**
> 这就是"某些比例正常、某些比例崩"的**唯一原因**——不是 UI 坏了，是画布形状变了。

**怎么查**：编辑器里 `Edit → Project Settings → Canvas`… 或直接看场景里 `ClientCanvas` 的 `CanvasScaler`（`m_ReferenceResolution` / `m_MatchWidthOrHeight`）。

---

## 2. 第二步：现象 → 锚点嫌疑（对照表，最实用）

| 现象 | 大概率原因 | 去看什么 |
|---|---|---|
| **左右/上下黑边、图不铺满** | ① 图开了 `Image.PreserveAspect` ② 锚点不是全屏 `(0,0)-(1,1)` | `Image.m_PreserveAspect`、`m_AnchorMin/Max` |
| **某个东西随比例变矮而"往下压/往上顶"** | 它是**中锚** `(0.5,0.5)` 或**顶锚**，而画布高度在变 | `m_AnchorMin.y` / `m_AnchorMax.y` |
| **两个元素随比例变化逐渐靠近直至重叠** | ⭐ **一个底锚 + 一个中锚/顶锚**（锚点类型不一致） | 两者的 `anchorMin.y/anchorMax.y` 是否**相同** |
| **宽屏被裁、窄屏有缝** | 水平锚点：该拉伸的设成了固定 | `m_AnchorMin.x` / `m_AnchorMax.x` |
| **列表只能显示几条、滑不动/松手弹回** | ① `ContentSizeFitter.verticalFit = Unconstrained`（内容不撑高）② `ScrollRect.movementType = Elastic` | 容器 `Content` 上的两个组件 |
| **只有 1 个条目时它跑到中间** | `GridLayoutGroup.childAlignment = MiddleCenter(4)` | 容器的 `m_ChildAlignment` |
| **文字/图标不显示** | 字段类型不匹配（TMP vs 旧版 Text）或未接线 | 组件字段 + 场景实际组件类型 |

## 3. 第三步：怎么"看到"这些值（三种手段）

1. **Unity Inspector（最快看单个）**：选中节点 → RectTransform → 点左上角**锚点方框**，看图钉落在父级的哪条边/哪个角（方框 vs 拉伸，一眼看出）。
2. **直接读场景 YAML（批量、可脚本化）**：Transform 块 `--- !u!224 &<id>` 里就是真值：
   ```
   m_AnchorMin / m_AnchorMax / m_AnchoredPosition / m_SizeDelta / m_Pivot
   ```
   注意：**中文节点名在 YAML 里是 `\uXXXX` 转义**，脚本比对前要 `[regex]::Unescape`。
3. **跑我留的审计脚本（一次看全部）**：
   ```powershell
   & 'D:\unity project\pinball\Logs\ui-adapt-audit.ps1'    # 21 页 × 布局规则
   & 'D:\unity project\pinball\Logs\ui-adapt-audit2.ps1'   # 标题/顶区
   ```

## 4. 第四步：修法（四条原则）

1. **同类元素统一锚点类型**：同一排/同一组的元素，要么都底锚、要么都顶锚 ⇒ 它们之间的**间距在任意比例下恒定**。
   > 本案例：`CanvasBottomFunction0` 是底锚 `(0.5,0)`，而 `CanvasBottomFunction1` 是**中锚** `(0.5,0.5)` ⇒ 让它也变底锚，问题根除。
2. **改锚点必须保持视觉位置**：把"中心锚 + 偏移 y"换成"底锚"时，偏移要换算成设计高度下的等效值。
   > 本案例：设计高 1630 ⇒ `398 = 1630/2 − 417`。
   > 改完先在**设计比例**下看一眼：位置没跳 ⇒ 换算正确。
3. **"铺满"和"保比例"是两件事**：
   - 要**铺满**：`preserveAspect = false`（可能轻微变形）
   - 要**保比例且覆盖**：用 `AspectRatioFitter → EnvelopeParent`（裁剪多余部分，不露边）
   - 要**保比例且完整显示**：`FitInParent`（会露边，一般不适合背景）
4. **只改与问题相关的那一个轴**。
   > 我踩过的坑：为了修"列表滑不动"，把容器的**水平也一起拉伸**了 ⇒ 容器变宽 ⇒ 整列卡牌被推到右半边。**最小改动优先**。

---

## 5. 第五步：验证与固化（防止"改好了又坏"）

1. **固定一组验证比例**：设计比例 + 极端比例，例如 **1.78（1080×1920）/ 2.0（1080×2160）/ 2.11（1080×2280）/ 2.17（设计）**。
2. **一次只改一个变量**，改完立刻在这组比例上扫一遍（Game 视图上方直接输分辨率）。
3. **备份 + 工具化 + 幂等**：
   - 场景改动前 `Copy-Item ClientShell.unity Logs/ClientShell.before-xxx.unity.bak`
   - 修正写成**编辑器工具方法**（`ClientShellStructuralRepair`），**可重复运行**、每次只报"改了几处"
4. **留证据**：工具日志（`Logs/repair-*.log`）+ 审计脚本报告 + 自检（`ClientSelfTest`）。这样换人/换会话都能接着做。

## 6. 本案例完整复盘（按五步走一遍）

| 步 | 动作 | 结果 |
|---|---|---|
| 1 | 算画布单位 | 参考 753×1630、按宽匹配 ⇒ 1080×1920 时**画布高只有 1339**（设计 1630） |
| 2 | 对现象 | ①黑边 → 查背景 `PreserveAspect` ②重叠 → 查两个底栏的 `anchorMin.y` |
| 3 | 读真值 | 背景：全屏锚点 **但 `m_PreserveAspect: 1`**；F0：`(0.5,0)`、offset 227；F1：**`(0.5,0.5)`**、offset −417 |
| 4 | 修 | ① `preserveAspect = false` ② F1 改底锚、offset `−417 → 398`（=1630/2−417） |
| 5 | 验证 | 在设计比例下位置不跳；工具幂等；备份 + 日志；极端比例复验 |

**算术验证"为什么会重叠"**：
- 高 1630：F1 距底 `815−417 = 398`，F0 距底 `227` ⇒ 间距 171 ✓
- 高 1339：F1 距底 `669.5−417 = 252.5`，F0 距底 `227`；半高 97 / 87.5
  ⇒ F0 顶边 `227+97 = 324` **>** F1 底边 `252.5−87.5 = 165` ⇒ **重叠** ✗

## 7. 常见坑清单（照单排雷）

- 中文节点名在场景文件里是 `\uXXXX` 转义 ⇒ 脚本比对前必须反转义
- **prefab 实例内部的节点不在场景文件里** ⇒ 静态扫描会漏；实例根节点的名字在 `PrefabInstance.m_Modifications`
- `GameObject.Find` **找不到未激活对象**（客户端页面/弹窗默认隐藏）⇒ 要用根节点深搜
- PowerShell 5.1 **按 ANSI 读 `.ps1`** ⇒ 脚本里不要写中文字面量（用字符码或从文件读）
- **`$ID` 是 PowerShell 内置只读变量**（`$ID` = 当前用户标识）⇒ 用 `$NODEID` 之类的名字，否则 `$ID.X` 解析成别的东西
- **`,` 的优先级低于 `+`**：`@($a + 'x', $b + 'y')` 会被当成**一个**元素（`$a + ('x', $b) + 'y'`）⇒
  每个元素要各自加括号：`@(($a + 'x'), ($b + 'y'))`。同理 `$lines + @('a' + $g + 'b')` 必须写成
  `$lines + @(('a' + $g + 'b'))`，否则拼进数组的字符串会被拆成多行。
- **正则字符类 `[-\d]` 是"范围 `\`..`d`"，不是"减号或数字"**（正确的数字类应写 `[0-9]`）。
  本仓库多个审计脚本沿用了 `[-\d]+`：碰巧因为"任何字符都落在 `\`..`d` 之间"而能匹配数字，
  但一旦要在后面接具体后缀（如 `, type: 3\}`）就会**静默失配** —— 写补丁脚本时务必用 `[0-9]`。
- 批处理 Unity 前**必须关掉已打开的编辑器**（否则 `HandleProjectAlreadyOpenInAnotherInstance` 崩溃，退出码 `0x40000015`）
- 改了锚点/尺寸后若"当前视觉位置跳了"⇒ 换算错了，不是 Unity 的锅
- **文本补丁场景文件时**：先备份；写完**重新解析**并断言目标值（本次 `Logs/apply-adapt12-text.ps1` 就是这么做的），
  再用 `Logs/check-scene-integrity.ps1` 对比备份的 document 集合（不能丢 document、不能有重复 fileID）；
  **首选仍是幂等编辑器工具**（`Client → 结构修复 → 7`），文本补丁只在编辑器占用、批处理跑不了时用
- ⭐ **编辑器可能在跑"旧编译产物"（2026-09-22 踩到，最难查的一个）**：
  点了自己刚写的菜单，日志也打了，但**改动只落了一部分**，看起来像"代码写错了"。
  **判别方法（不要靠猜）**：比对 `Library/ScriptAssemblies/Assembly-CSharp-Editor.dll` 的时间戳
  与 `Assets/**/*.cs` 的时间戳；更硬的证据是把该 DLL 的**原始字节**按 UTF-8 / UTF-16 各搜一遍
  你新写的那句日志字面量（`Logs` 里已有现成脚本 `scrollfix-blast-radius.ps1` 的读法可参考）：
  ```powershell
  $b=[System.IO.File]::ReadAllBytes('Library\ScriptAssemblies\Assembly-CSharp-Editor.dll')
  # 逐个字节找 UTF-8 编码的中文字面量，命中=已在程序集里
  ```
  本次实测：DLL 停在 09:35:58，而源码已改到 09:41:54 ⇒ **菜单 8 反复跑的都是旧版本**，
  两个 Viewport 一直没被修（Content 那部分旧代码也改，所以"改了一半"）。
  ⚠️ 相关脚本：`Logs/verify-compile.ps1` 是**独立 Roslyn 编译**，它绿**不代表编辑器 DLL 是新的**。
  **可靠解法**：① 点回 Unity 窗口 / `Ctrl+R` 触发重编（看 Console 出现编译完成），或
  ② **关掉编辑器用批处理**（`-executeMethod` 一定从源码全新编译）：
  `powershell -NoProfile -ExecutionPolicy Bypass -File Logs\repair-rank-batch.ps1`
  ⚠️ 别在菜单方法里调 `AssetDatabase.Refresh()` 想"顺手刷新"：脚本若真的被改过，
  它会触发**域重载**，把正在执行的方法直接打断（本次就是这么白跑一次的）。

## 1. 每次任务先做什么

1. 用 **PowerShell 7 `pwsh`** 运行 `git status --short`，识别已有修改、删除和未跟踪文件。不要重置、清理或覆盖负责人的改动。
2. 阅读 [AGENTS.md](../AGENTS.md)、[CURRENT_STATE.md](../CURRENT_STATE.md) 顶部交接快照。计划、实现或修复时再读 [DEVELOPMENT_WORKFLOW.md](../DEVELOPMENT_WORKFLOW.md) 和涉及目录的 `MODULE.md`；缺陷按编号查 [BUG_TRACKER.md](../BUG_TRACKER.md)。
3. 记录本次最小计划：目标、涉及模块、验收条件、验证方式、风险与待确认事项。只改本次任务直接相关的文件。
4. 开始实施前核对实际代码、场景和构建设置。历史文档有冲突，不能把旧阶段记录当成当前事实。

## 3. 数据与 UI 的正确接线

- `ClientServices.InitializeForDevelopment()` 先初始化 `Config`，再初始化本地 `Data` 和数值展示服务；`ClientBootstrap.Awake()` 调用它。不要颠倒配置与玩家数据的顺序。
- `ClientServices.Data` 是页面访问玩家状态的入口，接口为 `IClientDataService`，开发期实现为 `LocalClientDataService`。替换玩家数据服务使用 `ClientServices.ReplaceDataService(IClientDataService)`。真实网络适配器须等服务端契约，不在页面回调里临时实现。
- `ClientServices.Config` 读取静态配置，`ClientServices.Stats` 提供数值展示；目前 `LocalClientStatsGateway` 扮演服务端。不能把模拟结果写成正式服务器数值。
- UI 导航与弹窗入口见 `Assets/Client/Runtime/UI/`。按项目约束，页面已有场景节点时默认只改脚本和节点引用；不得自行新建 Page、重排 GUI 或替换素材。TMP 文本字段用 `TMP_Text`，旧 UGUI 文本才用 `UnityEngine.UI.Text`。
- 优先保证加载、空数据、拥有/未拥有、锁定、资源不足、领取失败、关闭与返回等状态闭环；业务规则必须经共享服务，不散落在 UI 点击回调。

## 5. 修改后的验证

- 纯 Markdown 改动：检查文本差异、链接和文件编码。
- C#、asmdef、项目配置或资源元数据影响 Unity 编译输入时：按 [AGENTS.md](../AGENTS.md) §3，交付前直接以 `D:\unity project\pinball` 为 `-projectPath` 运行一次 Unity 命令行编译，并记录退出码和日志位置。批处理子进程临时传 `ALLUSERSPROFILE=C:\ProgramData`，不写系统环境变量。
- 三目标离线编译入口：`pwsh -NoProfile -ExecutionPolicy Bypass -File 'D:\unity project\pinball\Logs\verify-compile.ps1' -Profile All`。它与项目要求的 Unity 命令行编译是不同的检查。
- 不代替负责人操作 Unity Editor、微信开发者工具或平台后台。需要 GUI 回归时，写清前置条件、点击路径、预期结果、失败排查与需要回传的证据。
- 同一实现路径首次失败后记录命令、症状与日志；取得新证据前不要原样重试。

## 6. 若任务要求重新导出小游戏

先按 [移植手册](../WEBGL_MINIGAME_HANDBOOK.md) 核对前置与环境。保存并关闭 Unity Editor 后使用 PowerShell 7：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File 'D:\unity project\pinball\Logs\webgl-port\run-pipeline-2phase.ps1'
```

脚本会强制结束本机名为 Unity 的进程。Phase A 准备程序集，Phase B 构建 YooAsset、WebGL 并转换小游戏。核对两阶段日志与退出码；导出后的上传、开发者工具预览和真机回归是后续独立步骤。上传内容按产物哈希与实际请求路径确定，不假设只需单个文件。未经授权不得上传或发布。

# 微信小游戏：两处导出物怎么用

接手时会看到两处要上传的文件：工程内 `Bundles/WebGL/DefaultPackage/<构建版本>/`，以及桌面导出目录 `弹珠接入text_1/720/webgl/` 下的两个 `.br`。它们属于不同的加载链路，不能互相替代。本文按当前工程（2026-09-23）说明，发布前以本次导出的文件和实际请求地址核对。

## 1. 每处文件负责什么

| 位置 | 内容 | 运行时作用 |
| --- | --- | --- |
| `Bundles/WebGL/DefaultPackage/<版本>/` | YooAsset 的 `.bundle`、资源清单和版本文件。资源包里可能有由收集器纳入的素材、Prefab、热更 DLL 等。 | `Boot/Init.cs` 初始化 `DefaultPackage`，查询版本与清单，再按资源地址下载对应 bundle。 |
| `webgl/<哈希>.webgl.data.unityweb.bin.br` | Unity WebGL Player 的压缩数据。包含构建进 Player 的场景和内置资源；当前 `Boot`、`ClientShell` 都在构建场景列表中。 | 微信小游戏启动时加载 Player 数据。 |
| `webgl/<哈希>.webgl.wasm.code.unityweb.wasm.br` | 压缩后的 WebAssembly 程序。包含 Unity 运行时及经 IL2CPP 编译的非热更 C# 代码。 | 微信小游戏启动时执行的程序主体。 |

`DefaultPackage` 文件夹里，`.bundle` 是具体资源；`PackageManifest_DefaultPackage.version` 给出当前资源版本；带版本号的 `PackageManifest_DefaultPackage_<版本>.bytes` 是运行时资源映射清单。构建报告等文件用于排查构建，不是游戏运行时需要的资源。不要把整个版本文件夹作为 OSS 上的新一层目录：客户端请求的是配置的 CDN 根地址加**文件名**。

两个 `.br` 的哈希文件名会随构建结果变化。相同导出目录下的 `minigame/game.js` 保存了本次 `DATA_FILE_MD5`、`CODE_FILE_MD5`；新文件传到 OSS 后，还必须让微信开发者工具使用**同一次导出的 `minigame` 工程**，否则旧 `game.js` 仍会请求旧文件。

## 2. 改了什么，要重新上传什么

| 本次修改 | 重新导出和上传的判断 |
| --- | --- |
| 只改交接文档 | 两处都不用动。 |
| 改 YooAsset 收集的图片、Prefab、热更资源 | 重建 `DefaultPackage`，上传新增或变化的 bundle 与对应清单；确认本次版本文件指向新清单。若两个 `.br` 未变化，不必重传。 |
| 改 `ClientShell` 场景节点、Player 内置的 `Resources` 或构建场景列表 | 重新生成并转换小游戏；通常 `data.br` 变化。若所改素材也被 YooAsset 收集，对应 bundle 和清单也要更新。 |
| 改 `Assets/Client`、`Init.cs` 等非热更 C# | 重新生成并转换；通常 `wasm.br` 和 `data.br` 都会变化。 |
| 改 HotFix C# | 先重新编译、同步 `HotFix.dll.bytes`，再重建包含它的 YooAsset 包；两个 `.br` 是否也变化，以本次完整导出的文件比较为准。 |
| 改微信转换配置、CDN 地址或 SDK | 重新生成并转换小游戏，核对 `minigame/game.js` 和实际请求路径；更新受影响的产物与小游戏工程。 |

这张表用于预判，**最后以新旧文件的哈希和文件名为准**。不要只因“只改了 UI”就直接决定传哪一个文件；同一张图可能进 Player，也可能进 YooAsset。旧哈希资源先保留，新的 bundle 与清单上传齐全后，再更新 `PackageManifest_DefaultPackage.version`，避免客户端拿到新版本号却找不到文件。

## 3. 在 Unity Editor 里手动导出

1. 保存场景和资源。打开 **File → Build Settings**，确认目标平台为 **WebGL**，启用的场景顺序为 `Assets/Main/Boot.unity`、`Assets/Client/Scenes/ClientShell.unity`。若刚切换平台，等 Unity 编译、导入结束。
2. 选择 **Build → WebGL → Compile And Sync HotFix DLL**，等待 `Assets/HotUpdateResources/Dll/WebGL/HotFix.dll.bytes` 更新并完成编辑器脚本重新加载。即使本次只改了页面，也按完整导出顺序处理，避免资源包与程序集版本不一致。
3. 选择 **YooAsset → AssetBundle Builder**。包选 `DefaultPackage`，管线选 `BuiltinBuildPipeline`，确认构建目标显示为 WebGL，填写本次 **Build Version**，点击 **Build**。成功后会打开 `Bundles/WebGL/DefaultPackage/<版本>/`。记下版本号；不要把不同构建版本的清单与 bundle 混在一起。
4. 选择 **微信小游戏 → 转换小游戏**，确认游戏资源 CDN 和导出路径，点击 **生成并转换**。当前配置的导出路径是桌面 `弹珠接入text_1/720`；`webgl/` 是 Unity/WebGL 导出物，`minigame/` 是要交给微信开发者工具的工程。“WebGL转小游戏(不常用)”只转换已有 WebGL 结果，不适合本次从源码完整重建。
5. 导出成功后，核对 `webgl/` 的两个 `.br` 文件名与同次 `minigame/game.js` 内的 `DATA_FILE_MD5`、`CODE_FILE_MD5` 一致，再比较上一版文件，列出本次实际变化。上传后用本次 `minigame/` 在微信开发者工具预览，并检查资源请求是否成功。

操作结果应看到：新的 YooAsset 版本目录、两个与 `game.js` 哈希对应的 `.br`，以及可打开的 `minigame/`。若没有产生对应文件，先看 Unity Console 的构建或转换报错；若文件已产生但小游戏卡在加载，先核对 `game.js`、CDN 地址、资源实际上传位置和请求返回状态。

## 4. OSS 路径：按当前源码，不照旧脚本默认值

当前 `Boot.unity` 的 YooAsset 主机地址与小游戏转换配置都指向同一 CDN 根目录。对 YooAsset，[Init.cs](<D:/unity project/pinball/Assets/Main/Init.cs:535>) 实际拼接方式是 `主机地址/文件名`；两个 `.br` 使用的 `dataFileSubPrefix` 也为空。因此**这两组当前运行所需文件都应放在该 CDN 根目录下，文件名保持原样**。上传后要以游戏实际请求的 URL 验证。

项目里的旧 [upload-to-oss.ps1](<D:/unity project/pinball/Logs/webgl-port/upload-to-oss.ps1:177>) 却将 YooAsset 文件放到 `/Assets/`，而且默认目录和 CDN 前缀是旧值，**不能直接照其默认值发布**。`/Assets/` 是微信 SDK 纹理等流式资源可能使用的路径，与当前 `Init.cs` 请求 YooAsset 清单和 bundle 的路径不同。

还要区分两件事：**上传 OSS**让远端文件可下载；**预览或提交新的 `minigame` 工程**让启动代码引用本次的哈希文件。这两步缺一不可。此处只记录操作关系，未执行上传或发布。

# 弹珠项目客户端交接

这份文档按接手时最常问的三个问题来写：现在能看到什么、TCP 数据怎样进来、新客户端的功能分别落在哪。源码位置均以 `D:\unity project\pinball` 为起点。以下是截至 2026-09-23 的工程快照；改接口或页面前，以当时的场景和源码为准。

## 1. 先用三分钟认清项目

这是 Unity 2022.3 的工程。原有 `Assets/Main` 和 `Assets/Scripts` 保留了旧游戏的启动、登录、战斗与网络代码；新增的非战斗客户端集中在 `Assets/Client`，主场景是 `Assets/Client/Scenes/ClientShell.unity`。构建场景顺序是 `Boot.unity → ClientShell.unity`，由 `Assets/Main/Init.cs` 的 `ClientStartScene` 决定首个客户端场景。

目前可以从主页进入个人中心、英雄、英雄详情、商店、邮件、排行、活动、编队及“成就指南”活动页。页面的玩家状态来自本地模拟服务，静态定义来自配置表，数值展示由本地数值网关提供。**页面能演示，不等于已接入正式服务端。** 2026-09-22 负责人确认过当时全部界面的 UI 验收；这不覆盖后续改动，也不代表真实账号、支付和正式环境已完成。

小游戏侧另有一条真实 TCP **诊断会话**：能取得网关、建连、握手、游客登录、请求并解析英雄回包，然后主动断开。它用于确认传输与当前几个协议可以工作，**没有把英雄回包写入 `ClientServices.Data`，页面仍显示本地模拟数据**。接手接口时，最要紧的是不要把这条验证链路误认为已完成业务接入。

## 2. TCP：连接怎样建立，包怎样分到协议

### 2.1 当前小游戏诊断链路

`Assets/Client/Runtime/ClientTcpConnectionProbe.cs` 是入口，挂在 `Boot`，实际会话迁移到跨场景对象，避免切换到 `ClientShell` 时中断。它等待 HotFix 中的 `NetController` 就绪，经反射调用 `NetController.GetIpPort`。这个方法先走 **HTTP 网关发现**，把地址写入 `SysDefines.Ip/Port`；拿到地址后，探针才调用微信 SDK 的 `WXBase.CreateTCPSocket` 建立 TCP 连接。

连接后的顺序是：

`OnConnect → CLGTHandReq(1/0) → CLGTHandAck(1/1) → CLGTLoginReq(1/3) → CLGTLoginAck(1/5) → CLPFGetHeroReq(2/1) → CLPFGetHeroAck(2/2) → 关闭连接`

握手使用平台号 6（WebGL）、产品号 1、`SysDefines.Version` 及设备、渠道、国家、语言字段。握手回包的 `random_key` 用于生成游客登录的 CA3 token；登录成功后才发空请求体的 GetHero。探针验证英雄和英雄组数组能完整读完后关连接。任一阶段遇到超时、错误码、异常长度或非预期协议，会走失败出口。PC 开发适配器在 `Assets/Client/Runtime/Services/ClientServerPcSession.cs`，使用 `TcpClient`，默认不允许自动连接；WebGL 下它只是保留场景引用的空组件。

### 2.2 一帧数据如何变成一个协议包

这个协议在 TCP 字节流上的包头固定 **8 字节**：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0–3 | `int32` | 整包长度，**包含这 8 字节包头** |
| 4–5 | `uint16` | 模块号 `mid` |
| 6–7 | `uint16` | 协议号 `pid` |
| 8 起 | 各协议自定义 | 按字段顺序读取的包体 |

源码用 `BinaryWriter/BinaryReader` 与 `BitConverter`，当前目标平台按小端读取。字符串不是以零结尾：先写 `uint16` 的 **UTF-8 字节数**，再写对应字节，字段还各有最大长度。权威字段顺序见生成代码 `Assets/Scripts/NetWork/JBPROTO/ClientGT.cs`、`ClientPF.cs`；字符串写法见同目录 `NetHelper.SafeWriteString`。这里的 `mid/pid` 常量、`toBinary/fromBinary` 比旧交接笔记更可信。

TCP 一次 `OnMessage` 不保证正好是一包。`ClientTcpConnectionProbe.OnMessage` 先把字节追加到 `receiveBuffer`，读到 4 字节长度后，等整包齐了再切出；一帧包含多包就循环处理。长度小于 8 或大于 1 MiB 会拒绝。完整包先交给 `ClientServerPacketRouter.Accept` 记录分类，再由探针的 `ParsePacket` 按 `mid/pid` 进入具体解析函数。发送端 `SendPacket` 先写占位长度、模块和协议，写完包体后回填总长度。

### 2.3 目前识别和处理了哪些协议

| 模块/协议 | 类型 | 当前实际处理 |
| --- | --- | --- |
| 1/0、1/1 | `CLGTHandReq/Ack` | 发送握手；应答读 `errcode、payload、random_key` |
| 1/2 | `CLGTDisconnectNtf` | 读断开码；英雄数据未收齐时判失败 |
| 1/3、1/5 | `CLGTLoginReq/Ack` | 游客登录；应答按生成类字段顺序读完，敏感画像不写诊断日志 |
| 2/1、2/2 | `CLPFGetHeroReq/Ack` | 空请求体；应答读英雄数组和英雄组数组并核对包尾 |
| 2/3–22 | `ClientPF` 个性化列表/操作协议 | **仅在记录器里按协议号分类**，当前诊断会话没有相应业务处理 |
| 其他 | 未知 | 记录器标为 `Unknown`；探针遇到非预期回包会结束会话 |

`ClientServerPacketRouter.cs` 的 `Accept/RecordOutgoing` 负责标注方向、长度、模块、协议名和分类，并写会话记录。它通过生成类的 `mid/pid` 查协议名，核心协议还有兜底名称；它**不负责把回包分发到页面或玩家数据服务**。它暴露 `PacketClassified` 事件，但当前也不是业务数据入口。可读记录和 JSONL 位于运行时 `Application.persistentDataPath/ClientServerLogs`；如启用原始抓包，`.packets.bin` 中每条记录还额外带一段 4 字节的抓包长度，不能把它误当成网络包头。

### 2.4 旧网络栈与新 Client 的关系

旧游戏原本已有 `Assets/Scripts/GameLogic/NetController.cs` 和 `Assets/Scripts/NetWork/JBPROTO/NetComponentImpl.cs`。`NetController` 注册各模块 `Responser`，它的 `Update` 调 `netComponent.run()`；底层 Socket 收到字节后，`NetData` 按长度拆包，`dispatchProtocols` 遍历已注册的 `processPackage`，生成协议类 `fromBinary` 后进入 `onRecv_…` 或等待中的回调。旧链路里也有 `SendGetHeroReq`，其回调走旧 `MessageCenter`。

因此接手时要区分：**生成的 JBPROTO 类是协议格式依据；旧 `NetComponentImpl/Responser` 是原游戏的收发分发；新 `ClientTcpConnectionProbe` 是小游戏验证会话；新 `ClientServerPacketRouter` 是分类和记录。** 目前这四者没有组成“服务器回包自动刷新新 Client 页面”的完整业务链。

## 3. 新 `Assets/Client` 有哪些模块

先记住一条主线：`ClientBootstrap` 初始化 `ClientServices`；页面通过 `ClientServices.Data / Config / Stats` 取数据；页面切换由 `ClientUiNavigator` 和 `ClientPopupService` 管。场景 `ClientShell.unity` 是界面节点与引用的落点，源码文件存在不代表场景里就能打开该页。

### 页面是怎样组织的

- **场景与导航**：`ClientBootstrap.cs` 初始化服务。主页留在 `PagesLayer`，其余已注册页面位于 `PopupLayer`，由 `UI/ClientUiNavigator.cs` 的 `Open/Back/ReturnHome` 导航；`UI/ClientPopupService.cs` 管弹窗栈、遮罩和关闭。页面只应通过 `IClientNavigation`、`IClientPopupService` 发起切换。
- **主页、个人中心**：`ClientHomePage.cs` 管大厅入口，`ClientHomeRedDotController.cs` 管红点；`ClientProfilePage.cs`、`ClientHomeShowcasePage.cs`、`UI/ClientCollectionList.cs` 管资料、主页展示英雄和收藏品。数据入口是 `GetProfile/TryRename/GetOwnedCollectionIds/TryEquipCollection/TrySetShowcaseHero`。
- **英雄、编队**：`ClientHeroPage.cs`、`ClientHeroDetailPage.cs` 显示列表、拥有状态、详情、升级和升星；`ClientFormationPage.cs` 管四队、每队三槽的本地编队。相关接口是 `GetHeroes/GetHeroDetail/TryUpgradeHero/TryStarUpHero/GetHeroAbilityUpgradePreview/TryUpgradeHeroAbility` 以及 `GetFormationTeams/TrySwitchFormationTeam/TryToggleFormationHero/GetFormationCombatPower`。编队数量来自现有场景，正式规则仍待确认。
- **商店、邮件、排行**：`ClientShopPage.cs` 显示商品、限购数量和本地购买反馈，对应 `GetShopListings/GetShopPurchasedQuantity/TryPurchaseShopListing`；`ClientMailPage.cs` 对应 `GetMails/TryReadMail/TryClaimMail/ClaimAllMails/TryDeleteAllMails`；`ClientRankPage.cs` 对应 `GetLeaderboardEntries/GetPlayerLineup`。
- **活动、任务**：`ClientActivityPage.cs` 和 `ClientCompleteGuideEventPage.cs` 使用 `GetActivities/GetActivityTasks/TryClaimActivityTask/GetCompleteGuideEvent/TryClaimCompleteGuideEvent`。任务的数据接口 `GetTasks/TryClaimTask` 和 `ClientTaskPage.cs` 已有，但主页任务入口当前不可路由。
- **通用反馈**：`ClientLoadingPage.cs`、`ClientLoadingService.cs` 提供加载展示；`UI/ClientSystemFeedback.cs` 提供提示。TCP 诊断的三个入口见上节，它不属于页面业务模块。

上表省略了部分页面内的显示组件，目的是先找到业务入口。**场景中按 PageId 可路由的弹窗**在最近一次源码记录里是个人中心、英雄、英雄详情、商店、邮件、排行、活动、编队、成就指南这 9 个。扭蛋、背包、任务、公告、弹珠虽然保留了枚举或部分数据/脚本，主页目前通过 `CanOpenFromHome` 拦截并提示“开发中”；不要只看 `ClientUiPageId` 或类名就写成已交付页面。后续若场景改过，直接以 `ClientShell.unity` 中的注册与节点为准。

### 三个接口边界，接真实数据时先看这里

1. **静态配置**：`IClientConfigService` 回答游戏里有哪些英雄、收藏品、道具、技能和潜能。实现 `TableClientConfigService` 读取原工程的表，页面不直接依赖 `T*Helper`。
2. **玩家状态与操作**：`IClientDataService` 回答玩家拥有、等级、货币、购买、领取、编队等状态；成功修改后通过 `DataChanged` 通知页面刷新。当前实现 `LocalClientDataService`。接服务端时可从 `ClientServices.ReplaceDataService(IClientDataService)` 换掉玩家数据实现，但还要处理会话、回包映射、错误码和状态同步，不能只替换这一行。
3. **数值展示**：`IClientStatsService` 提供属性与能力状态查询；当前 `LocalClientStatsGateway` 扮演服务端数值来源。真实数值应按服务端契约接入，不能把本地演示数值当权威。

配置表对应的英雄、道具、收藏品等 ID 在 Client 接口里主要是 `int`；邮件、商品、活动、任务、玩家等服务端对象标识是 `string`。要改接口，先对照 `Domain` 模型与对应接口，再改服务实现和页面绑定，避免在 UI 回调中另造一份规则。

## 4. 接手后从哪里找

| 遇到的工作 | 首先看 |
| --- | --- |
| 页面入口点了没反应、返回遮罩异常 | `ClientShell.unity` 的页面注册；`UI/ClientUiNavigator.cs`、`UI/ClientPopupService.cs` |
| 页面数据不对、需要改真实接口 | `Services/IClientDataService.cs`、`ClientServices.cs`、`LocalClientDataService.cs`，再看对应页面 |
| 英雄或收藏品内容不对 | `Services/IClientConfigService.cs`、`TableClientConfigService.cs`、`Domain/`；确认是配置、拥有状态还是资源映射的问题 |
| TCP 连接或协议不对 | `ClientTcpConnectionProbe.cs` 的建连与拆包；`ClientServerPacketRouter.cs` 的分类；`JBPROTO/ClientGT.cs`、`ClientPF.cs` 的字段顺序；旧链路再看 `NetComponentImpl.cs` |
| 小游戏导出与 OSS 上传范围 | 先读 [微信小游戏资源导出与上传](./01_微信小游戏资源导出与上传.md)；再按需查 [小游戏移植手册](../WEBGL_MINIGAME_HANDBOOK.md) |
| 真机现象和历史问题 | [真机记录](../WEBGL_B2_REALDEVICE.md)、[风险台账](../BUG_TRACKER.md) |

目前最明确的后续接口工作是：取得正式服务端契约，把 TCP 回包解码成 Client 的领域数据，接入玩家状态与数值来源，并验证页面刷新和错误态。服务端协议范围、正式账号、支付、平台能力及发布条件尚未由这份客户端工程定义。小游戏已有首轮真机通过记录；弱网、后台切回、内存峰值等深度项仍需按 [真机记录](../WEBGL_B2_REALDEVICE.md) 补验。

进一步查整体历史可读 [开发交接总稿](../HANDOVER_DEV.md)；它是资料库，不是理解新 Client 的第一站。给编码代理的执行约束另在 [AI 交接](../01_给AI看/00_执行交接.md)。
